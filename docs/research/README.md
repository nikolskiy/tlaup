# Investigation results (pipeline stage 2)

One file per question on the roadmap's investigation list, numbered as there. Each file has the question, its source, a short answer, a confidence, the evidence, the implications for the roadmap and open follow-ups. Captured data is under `tests/fixtures/research/NN-*/`; the testing design confirms or moves it.

All questions were run on 2026-11-14 (local time; the machine clock and GitHub read 2026-11-15 UTC), on Linux with OpenJDK 25.0.5. Java 11 was not installed. On that day `rolling` and `v1.8.0` held the same `tla2tools.jar` (SHA-256 `7e53aa63...fb84f`, commit `bc1b506`, CalVer `2026.11.15.002146`), so every "1.8.0" result also covers the rolling build of that day. `v1.7.4` is commit `5a47802`.

## Stage 2 check

Every file was read against its evidence. The main claims were rerun or rechecked in this session on 2026-11-14: TLC exit codes for violation, deadlock, assertion, liveness, parse and semantic errors and a missing cfg on both jars; SANY semantic-error exit 0; `-dumpTrace` absent from v1.7.4 and present in 1.8.0; tag and release counts, the page-one cutoff, `prerelease` flags, `latest` and digests from the API; the dispatch step and the push-only release guard in both workflows; the Examples outcome enum; the nightly jar's size and date; the manifest commit and build time; the build logs of question 6; and the tlaup code that questions 7, 8, 13, 16 and 17 describe.

One correction was made: question 13 first said tlaup never passes the examples' override classes. That is wrong, because `modules add` writes a service file that names them. Running `docs/examples/QueueModule` showed that the override loads on 1.8.0 and silently does not load on v1.7.4. The file now says so.
